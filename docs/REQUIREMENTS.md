# Требования к Flight Bridge (для команды)

Документ на русском, простым языком. Источники: материалы Дениса
(`PROJECT_STATUS.md` / `CONTINUE_HERE.txt` с его машины — **в репозиторий не
коммитятся**) и актуальная спецификация администратора. Личные пути, имена
пользователей, Steam ID, имена машин и адреса почты сюда **не входят**; вместо
них — шаблоны вроде `%USERPROFILE%`, `%LOCALAPPDATA%`, `<SteamID>`.

> Важно: у Дениса в handoff описана версия **0.3** (ручной выбор XML). В этом
> репозитории уже **0.5.1**, где автоматическое обнаружение, полный бэкап,
> запись на месте и откат **уже есть**. Ниже — что из требований уже сделано в
> 0.5.1, а чего ещё нет (сверка с кодом, не с маркетингом).

Подробности «как сейчас устроен код»: [LOGIC.md](LOGIC.md).

---

## 0. Главный принцип: «Запустил и работает»

Философия как у Apple: человек **запустил программу — и она сделала дело**.

Пользователь **никогда** не выбирает папки, пути или файлы и **не обязан** знать,
стоит ли у него Steam или Microsoft Store и где лежат данные. Программа сама
находит обе игры в любой комбинации и сама переносит привязки.

Каждое решение команды проверяется одним вопросом: **придётся ли человеку что-то
выбирать или разбираться?** Если да — переделать.

Конкретно:

- аккаунт Steam выбирается **автоматически** (тот, у кого есть папки
  `1250410` / `2537590` с профилями); спросить только если таких аккаунтов
  несколько;
- папка резервной копии — **по умолчанию**, без вопроса на главном экране
  (в крайнем случае — мелкая вторичная ссылка вроде «куда сохранять копии», не
  основной шаг);
- все сообщения — человеческим языком, **без путей** и без слов вроде «WGS» или
  «XML» в интерфейсе;
- **единственные** допустимые выборы пользователя: несколько аккаунтов Steam
  (если иначе нельзя) и **одно подтверждение** переноса.

## 1. Главный сценарий (обязательный)

Одна понятная кнопка. Программа сама:

1. Находит MSFS 2020 и MSFS 2024 (Steam, Microsoft Store / Xbox, в том числе
   **смешанная** установка).
2. Находит профили контроллеров и **сама** сопоставляет устройства.
3. **Не** просит в обычном сценарии выбирать папки или XML-файлы.
4. Перед записью проверяет, что закрыты MSFS 2020, MSFS 2024 и Steam (если
   задействован Steam); если нет — одно ясное действие («закройте …»).
5. Делает **полный** бэкап исходного и целевого хранилища (данные Store/Xbox и
   Steam Cloud) с манифестом и SHA-256. Папка по умолчанию — понятная в Documents
   (например `%USERPROFILE%\Documents\Flight Bridge\Backups`), **без вопроса**
   на главном экране. Смена каталога — только как мелкая вторичная ссылка, не
   обязательный шаг.
6. Показывает предпросмотр «что куда пойдёт / что будет пропущено» и запрашивает
   **одно обычное подтверждение**.
7. Пишет только в **уже существующие зарегистрированные** профили MSFS 2024.
8. Запись атомарная; после записи XML перечитывается и проверяется; при любой
   ошибке — автоматический откат.
9. Никогда не пишет и не создаёт `containers.index` и не создаёт новые файлы облачного хранилища Store «с нуля»
    (технически: корень `wgs`; в UI слово «WGS» не показывать).
10. Заметная кнопка «Вернуть как было» с проверяемым восстановлением по манифесту
    (отказ, если пользователь уже изменил профиль в игре после переноса).

Интерфейс: спокойный; на главном экране нет путей, терминов вроде WGS/XML и лишних настроек (см. принцип §0).

### Решения команды по сопоставлению (в силе)

- **Категория** профиля 2020 с источником **не сравнивается** (у профилей 2020
  часто нет `CategoryName`). Категория берётся у **цели 2024**; если у цели нет
  категории — это «Общее» (General), с предупреждением «проверьте импорт в игре».
- Однозначный перенос команд `KEY_*` в другой контекст (**relocation**) остаётся
  **включённым**; каждая такая перестановка видна в предпросмотре как
  предупреждение.
- **GUID** устройства — только подсказка-тайбрейк, если кандидатов несколько;
  основное сопоставление — ProductID + имя (см. код).

## 2. Запасной сценарий (только если автозапись невозможна)

Если безопасная автоматическая запись в игру невозможна:

- показать **ровно один** конкретный следующий шаг;
- предложить **экспорт файла** для ручного Import внутри MSFS 2024;
- сформировать **обезличенный** диагностический отчёт (без имён пользователей,
  полных путей, Steam ID, GUID устройств, имён профилей).

Это **не** основной путь. Основной — запись в уже зарегистрированные профили.

---

## 3. Режим «только диагностика»

Отдельный режим / первый запуск на ПК с симуляторами:

- только чтение;
- ничего не меняет в хранилищах игр;
- показывает, что найдено (редакции, типы Store/Steam, число профилей, блокеры);
- удобен до первого реального переноса, особенно на машине с Store/Xbox (см. §5).

## 4. Steam Cloud и файл `remotecache.vdf` (обязательно)

У Steam в корне облачных данных приложения лежит `remotecache.vdf`: там SHA и
метки времени облачных файлов. Программа:

- **никогда не изменяет и не удаляет** `remotecache.vdf` (и не должна иметь
  кода записи в него);
- после успешной записи в Steam `remote` в результате / notices должно быть
  понятное предупреждение: при следующем запуске Steam может показать конфликт
  облака — нужно выбрать загрузку **локальных** файлов на облако, иначе облако
  вернёт старые привязки.

Ориентиры по поведению конфликтов (внешние обсуждения, не спецификация Valve):

- https://github.com/ValveSoftware/steam-for-linux/issues/10014
- https://flyawaysimulation.com/ask/answers/fix-steam-cloud-out-of-sync-error/

Автотест (планируется / обязателен в CI): хеш `remotecache.vdf` до и после
переноса совпадает.

Типичные пути (шаблоны):

- Steam 2020: `%PROGRAMFILES(X86)%\Steam\userdata\<SteamID>\1250410\remote`
  (библиотеки Steam могут быть на других дисках; путь Steam — из реестра).
- Steam 2024: `...\userdata\<SteamID>\2537590\remote`
- Рядом с `remote` — `remotecache.vdf` (не трогать).

## 5. Microsoft Store / Xbox (`wgs`)

Типичные корни (как в коде 0.5.1):

- 2020: `%LOCALAPPDATA%\Packages\Microsoft.FlightSimulator_8wekyb3d8bbwe\SystemAppData\wgs`
- 2024: `%LOCALAPPDATA%\Packages\Microsoft.Limitless_8wekyb3d8bbwe\SystemAppData\wgs`

Внутри — `containers.index`, каталоги с `container.*` и файлы профилей с
непредсказуемыми именами. Новые записи в WGS **нельзя выдумывать**: только
обновление содержимого уже зарегистрированного файла профиля 2024 после полного
бэкапа.

Поведение облака Xbox / Store **после правки существующего файла** надёжными
публичными источниками **не подтверждено**. Поэтому на ПК с симулятором сначала
рекомендуется режим «только диагностика», затем перенос с обязательным бэкапом и
проверкой в игре.

## 6. Сборки и подпись

На выходе нужны:

- установщик (`Setup` / `INSTALL …exe`);
- портативный `FlightBridge.exe` и ZIP —

как в актуальном `build.ps1` репозитория (папка
`dist\Flight Bridge 0.5.1 - CURRENT\` и т.п.).

Публичной Authenticode-подписи нет и **нельзя** подменять её самоподписью
«для галочки». Предупреждение Windows о неизвестном издателе — ожидаемо.

## 7. Уже есть в 0.5.1 vs ещё нет

Сверка с кодом (`AutoMigration`, `MigrationTransaction`, `AutomaticApp`,
`Engine` / `Library`, `build.ps1`).

| Требование | В 0.5.1 |
|------------|---------|
| Автопоиск 2020/2024, Steam + Store/WGS, mixed | **Есть** (`AutoMigration.Discover`) |
| Автосопоставление устройств (ProductID + имя), без ручного XML | **Есть** (`CompatibleSources` / `Build`); GUID как тайбрейк — **нет** |
| Проверка, что симуляторы и Steam закрыты | **Есть** (`RequireClosed`) |
| Полный бэкап корней + SHA-256 + журнал | **Есть** (`MigrationTransaction`) |
| Папка бэкапа по умолчанию в Documents (без вопроса на главном экране) | **Есть** (смена каталога сейчас есть во свёрнутом разделе — по принципу §0 должна стать не более чем мелкой вторичной ссылкой) |
| Запись только в существующие зарегистрированные профили 2024 | **Есть** (`Registered`) |
| Не писать / не создавать `containers.index` и новые WGS-файлы | **Есть** (запись только в уже найденный файл профиля) |
| `remotecache.vdf` не изменяется кодом записи | **Фактически да** (только чтение при проверке регистрации); **явного теста хеша и notices про конфликт облака — нет** |
| Атомарная запись, проверка XML, автооткат | **Есть** |
| Кнопка восстановления с проверкой манифеста / отказом при позднем изменении | **Есть** («Вернуть…») |
| Предпросмотр «что куда / что пропущено» + **одно** подтверждение перед записью | **Нет** (есть раскрывающиеся подробности и сразу запись; MessageBox — после успеха) |
| Режим «только диагностика» в UI (ничего не меняет) | **Частично**: есть обезличенный отчёт и отдельный diagnostics exe в сборке; отдельного режима первого запуска в UI — **нет** |
| Fallback: экспорт для Import + ровно один следующий шаг, если автозапись невозможна | **Нет в UI** (`Engine.Export` / `Library.ExportBatch` есть, но UI ими не пользуется) |
| Предупреждения по General / relocated `KEY_*` в предпросмотре | **Частично**: relocation включён (`allowRelocated: true`), предупреждения в плане; отдельного обязательного экрана предпросмотра — **нет** |
| Setup.exe + portable + ZIP | **Есть** в `build.ps1` (publish в `dist\… - CURRENT`) |
| Спокойный UI без путей/jargon на главном экране; единственные выборы — несколько Steam-аккаунтов и одно подтверждение | **Частично**: путь бэкапа и смена каталога ещё видны во свёрнутом разделе; отдельного обязательного подтверждения перед записью нет |
| Не фабриковать code signing | **Соблюдается** (подпись только при явном thumbprint) |

## 8. Чего сознательно нет в этом PR

Этот документ и правки README/LOGIC **не меняют поведение** программы. Реализация
недостающего (предпросмотр+подтверждение, diagnostics-only, fallback export,
notices про Steam Cloud, тест неизменности `remotecache.vdf`, упрощение UI под принцип «Запустил и работает») — отдельные PR.
